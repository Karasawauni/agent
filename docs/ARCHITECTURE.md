# 構成と決定事項

## 目的
動画制作を、Claude Codeを窓口にして、クラウドで回す。PCがなくても、スマホから素材と完成物を確認できるようにする。

## 役割分担
| 役割 | 担当 | 備考 |
|---|---|---|
| 窓口・指揮 | Claude Code | 全作業の入口 |
| コード・プロンプト・設定 | GitHub | 素材と認証情報は入れない |
| 素材・`.blend`・完成物（正本） | Googleドライブ | スマホで確認できる |
| Blenderの操作 | ローカルPC | 画面を見ながらの調整 |
| Blenderのレンダリング | Modal（GPU） | ドライブから取得し、結果を戻す |
| 1枚目の画像 | Adobe Firefly（Pro Plus、**手動実行**） | 人がWebアプリで生成し、ドライブへ保存する。API・MCP・ブラウザ自動操作は使わない（下記） |
| 画像の後処理 | Adobe MCP | 背景除去、リサイズなど。画像生成は不可 |
| 動画生成 | Higgsfield（必要ならModal） | まずHiggsfieldで始める |
| 認証情報 | Claude Codeの環境変数、Modal Secrets | GitHub Secretsは使わない |
| AWS | 使わない | 必要になったら追加（Secrets Managerの学習など） |

## 基本の流れ
1. ローカルのBlenderで構図を作り、`.blend`をドライブへ置く。
2. Claude Codeに依頼し、Modalでレンダリングする。結果はドライブへ保存する。
3. （手動）Claudeが作ったプロンプトで、FireflyのWebアプリから1枚目の画像を生成し、ドライブの`frames/`へ保存する。
4. Higgsfieldで動画にする。
5. 完成物をドライブへ保存し、スマホで確認する。

## リポジトリ構成
| リポジトリ | 役割 |
|---|---|
| agent | 共通の道具箱。常に主役 |
| video-〇〇 | 作品固有のもの。作品ごとに作る |

- Organization、GitHub Projectsは、数が増えるまで使わない。
- 変更は、リポジトリごとに別々にコミット・プッシュする。

## セッションの運用
- agentを主役にして、作品リポジトリを、セッションごとにアタッチする。
- 新しくリポジトリを作ったら、必ずアタッチする。
- 1つの作業につき、1つのセッションにする。
- 決定事項は、チャットではなく、リポジトリのファイルに残す。
- 作業の終わりに、必ずプッシュし、素材はドライブへ保存する。

## ドライブのフォルダ構成
Gitでは管理せず、リポジトリ名と同じ名前のフォルダを、ドライブに作って管理する。

```
Googleドライブ/
└── Git/
    └── video/
        ├── video-〇〇/    # リポジトリ名と同じ
        │   ├── assets/   # 素材（参照画像など）
        │   ├── blend/    # .blend
        │   ├── renders/  # Modalのレンダリング結果
        │   ├── frames/   # Fireflyの1枚目の画像
        │   └── final/    # 完成動画
        └── video-△△/
```

- 作品リポジトリの`CLAUDE.md`に、対応するドライブのフォルダ名を書く。
- 作品の中のサブフォルダの分け方は、仮の案。使いながら調整する。
- agent用の素材フォルダは、必要になったら作る。

## 置き場所のルール
- 他の作品でも使うPythonはagent、この作品だけのものは作品側に置く。
- 迷ったら作品側に置き、2作品目で使いたくなったらagentへ移す。
- 画像・動画・`.blend`は、Gitに入れない。正本はドライブに置く。

## 認証情報
- チャット、コード、コミットに書かない。
- 用途ごとに、最小権限の鍵を分ける。
- 鍵を作り直したら、置き場所をすべて更新する。

## Fireflyの扱い（確認済み）
- Adobe MCP（Claudeコネクタ）は、テキストからの画像・動画生成を公開していない（Adobe社員の公式回答、2026-09-02）。
- Firefly APIは、Pro Plusでは使えなかった（Developer Consoleで利用できず、ユーザー確認済み）。
- ブラウザの自動操作は、Adobeの規約（自動化・スクリプト処理の禁止、アカウント無効化の可能性）に抵触しうるため使わない。
- そのため、Fireflyでの生成は**手動**とする。動画化など、自動化する部分はHiggsfieldで行う。
- AdobeがMCPやAPIで個人プランに生成を開放したら、再検討する。
