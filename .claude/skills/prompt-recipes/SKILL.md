# プロンプトの型（2026-11 改訂）

出典: ComfyStudio「動画生成AIのプロンプト書き方＆例文2026」、Adobe Firefly「アニメーション動画の作例」（11例）、このプロジェクトでの実験。
**書く前に、使うモデルの入力制約を確認する**（下の「モデルの入力制約」）。

## 0. 基本の考え方
- **画像からの動画化（i2v）は、「動き」を書く。外見は書かない。** 外見は最初のフレームが決めている。外見だけ書くと、ほぼ静止画になる。
- 外見を変えたくない部分は「〜は最初のフレームのまま」と1文で固定する。
- 文章からの動画化（t2v）は、外見と動きを両方書く。

## 1. 動画プロンプトの順番（基本）
`主体 → 動作 → カメラ → 光 → 雰囲気・スタイル → 制約`

| 要素 | 書き方 |
|---|---|
| 主体の動作 | 動詞を主語のすぐ後ろに置く。主要な動きは1つ＋わずかな副次の動き |
| カメラ | 映画用語で具体的に（下の表）。「ダイナミックに」などの抽象語は使わない |
| 速度・質感 | 「ゆっくり」「滑らか」「スローモーション」など、1語だけ添える |
| 光・環境 | 「夕焼けの逆光」「ネオンの反射」など、1語で |
| 制約 | `No logos, no signs, no numbers, no readable text anywhere.` を1行だけ |

- 英語のほうが、動きの指示は通りやすい。英語で書き、日本語訳を添えてユーザーに見せる。
- 5秒前後なら、80〜120語（日本語で2〜4文）が目安。

## 2. 失敗例と直し方
| 失敗 | 直し |
|---|---|
| 外見だけで動詞がない（「制服の少女、長い黒髪、教室」） | 「少女がこちらを向いて微笑む。カメラはゆっくりズームイン」 |
| 大きな動きを複数同時に（振り返る＋手を振る＋髪が舞う＋猫が跳ぶ） | 1つに絞る。「髪はわずかに揺れる程度」 |
| 抽象語だけ（「エモーショナルな演出」） | 具体的な動作に直す。「ゆっくり目を閉じる。カメラは静止。柔らかい光」 |

## 3. カメラ用語表
**動き**

| 英語 | 動き |
|---|---|
| slow zoom in / push in | 被写体へ寄る |
| zoom out / pull back | 引く |
| pan left / pan right | 左右に振る |
| dolly in / dolly out | 前後に移動（空間に入る感じ） |
| orbit clockwise / counter-clockwise | 周回 |
| tracking shot | 動く被写体を追う |
| static camera / locked off | 固定 |
| handheld, natural sway | 手持ちの自然な揺れ |

**ショットサイズ**: close-up / medium close-up / medium shot / full shot / wide shot / extreme wide shot
**アングル**: eye-level / low angle / high angle / bird's-eye view
サイズとアングルは別の軸。掛け合わせて指定する（例: low angle, full shot）。

## 4. 動きの強さ
- ごく穏やか（最も安定）: `Very subtle motion: only the hair and eyes move slightly, everything else nearly still.`
- 標準: `Moderate movement: [subject] turns and gestures naturally, with a gentle camera drift.`
- 激しい動きほど破綻しやすい。激しくするときは、動きを1つに絞る。
- 一部だけ動かす（シネマグラフ）: 「シーンは完全に静止。〇〇だけが動く」と書く。ループにしたいときは「loopable」と書く。

## 5. 長尺（8秒以上）は、秒数ごとに書く
1つの文章で長い動きを書くと、動きがぼやける。**時間帯ごとに区切って、各区間に1〜2個の出来事だけ書く。**

```
全体: 条件（構図・固定要素・色味・カットなし）
0-4s: 〇〇。カメラは〇〇
4-6s: 〇〇
...
最後の区間: 次のショットの最初につながる状態で終える
```

- 区間の長さは、Blenderなどの参照があれば、そのタイミングから決める。
- 各区間は、一文か二文にする。区間を詰め込まない。
- 全体の長さが長いほど、区間の出来事を減らす。うまく動かなければ、長さを分けて、終了フレーム（`end_image`）でつなぐ。
- 時間どおりに動く保証はない。ずれたら、区間の文言を直して再生成する。

## 6. Blenderの動きを言葉にする手順
1. カメラとオブジェクトの位置を、フレームごとに読み出す（`bpy`で`frame_set`して`matrix_world`を見る）。
2. 変化が起きるフレームを探す。これを秒数に直す（フレーム÷fps）。
3. 起きることを、上の表の言葉に置き換え、区間に割り当てる。
4. 推測で足さない。分からないことは「要確認」として、ユーザーに聞く。
5. 注意: `bpy.data` は、`open_mainfile` しないと、初期シーンが見える。必ず開いてから調べる。

## 7. 画像（1枚目のフレーム）
`被写体 + 状況/動作 + 場所 + 光 + カメラ/レンズ + 質感/色味 + 禁止要素`

- スマホで撮った自然な実写風にする場合は、`realistic-first-frame-image` スキルに従う。
- 参照画像は、番号と役割を決め、「それ以外は無視」と書く。
- キャラクターは、キャラクターシートを画像で渡す。文字の説明だけだとアニメ調になる。

## 8. モデルの入力制約（確認してから書く）
- **MAGI-2（`magi_2`）**: 最初のフレーム（`start_image`）は、参照メディアと同時に使えない。「最初のフレーム」か「参照（画像・動画・音声）」のどちらかを選ぶ。長さ4〜30秒、1080p。
- つなぎ目を合わせたいときは、最初のフレームを使う。カメラの動きは、プロンプトの言葉で伝える。
- 参照動画を使うと、最初のフレームは指定できない。
- ほかのモデルの制約は、`models_explore` の `get` で確認する。モデル名やバージョンの優劣を、記憶で断定しない。

## 9. 一貫性のルール
- キャラ・場所・色味は「固定要素」として、全カットのプロンプトに同じ文で入れる。
- 画面内の文字、細かい手元、群衆は破綻しやすい。後から編集で足す。
- 気に入った結果は、seed を記録し、プロンプトを1要素ずつ変えて比べる。

## 10. 生成前の確認（必須）
次を見せて、OKをもらってから実行する。
1. プロンプト全文（英語と日本語訳）
2. 参照の対応表（ファイル、役割）
3. 設定（モデル、長さ、縦横比、音）と、クレジット（見積もり、無料生成の残数）
